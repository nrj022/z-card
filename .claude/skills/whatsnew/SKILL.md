---

## 기준
- 버전: app/build.gradle.kts의 baseVersion 값 (예: 1.10.0 → v1.10.0)
- 범위: baseVersion보다 낮은 버전 태그 중 가장 최신 태그(예: v1.9.0)부터 HEAD까지의 develop 변경사항
  - 출시노트 커밋 이후에 merge된 브랜치가 이전 버전에 포함됐을 수 있으므로 커밋 메시지가 아닌 태그 기준
  - 해당 태그가 없으면 작업하지 말고 알려줘
- 이미 해당 버전 출시노트가 있으면 작업하지 말고 알려줘

## 작성 규칙
- distribution/whatsnew 아래 모든 언어 파일을 이번 버전 내용으로 통째로 교체 (이전 버전 내용은 남기지 않음)
- 기존 파일 구조 유지: 제목 줄 → 한 줄 요약 → `- ` 항목들 → 기존 마무리 문장 그대로
- 사용자가 체감하는 변경(feat, fix, ui)만 포함. test, build, refactor, chore, ci, docs와 내부 구조 변경은 제외
- 기술 용어 대신 사용자 입장의 표현 사용
- 언어별 말투는 기존 파일을 따르고, 영어는 직역하지 말고 자연스럽게
- 각 파일 500자 이하 (Play Console 제한)
- 포함할 변경이 없으면 작성하지 말고 알려줘

## 진행
1. 범위 안 커밋 목록과 출시노트에 넣을 항목 / 제외할 항목을 먼저 보여줘
2. 각 언어 파일 작성 후 글자 수와 함께 보여줘
3. distribution/whatsnew 아래 파일만 커밋해. 이미 스테이징된 다른 파일은 포함하지 말고 그대로 둬
   - 커밋 제목: `docs: v1.10.0 출시노트 업데이트` (버전은 baseVersion 기준)
   - 본문, 이슈 번호, Co-Authored-By 같은 트레일러는 붙이지 마
4. push는 절대 하지 마. 커밋 후 커밋 해시와 제목을 알려줘
